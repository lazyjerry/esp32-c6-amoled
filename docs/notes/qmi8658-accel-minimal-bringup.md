## 結論
只要加速度計的話，三個暫存器就夠：

```
CTRL1 (0x02) = 0x40   // ADDR_AI：位址自動遞增
CTRL2 (0x03) = 0x26   // aFS=±8g, aODR=125Hz
CTRL7 (0x08) = 0x01   // aEN
```

資料在 `0x35`~`0x3A`，小端、`int16`，±8g 檔位是 **4096 LSB/g**。從 `0x35` 一次連讀 6 個 byte 即可，不需要陀螺儀、不需要 FIFO、不需要接 INT 腳。

## 為什麼
- 沒有 `CTRL1` 的 `ADDR_AI`（bit6），連續讀取不會自己遞增位址，六個 byte 會拿到重複或錯位的值——三軸看起來全是雜訊，但每個暫存器單獨讀又是對的。
- 量程與輸出率同在 `CTRL2`：bit[6:4] 是 `aFS`、bit[3:0] 是 `aODR`。`0x26` = `010`（±8g）+ `0110`（125Hz）。甩動的峰值輕鬆超過 2g，用預設的 ±2g 會削頂，偵測門檻就失去意義。
- `CTRL7` 不設 `aEN` 的話晶片會回應 I2C、`WHO_AM_I` 也正確，但資料暫存器恆為 0，很容易誤判成接線問題。

## 驗證
初始化後先讀一次並印出合力，**靜置時應該接近 1g**：

```
I imu: QMI8658 就緒，靜置 1.07 0.01 -0.02 g（合力 1.07）
```

合力若是 0.5g 或 4g 之類的整數倍偏差，是量程算錯（`LSB_PER_G` 與 `aFS` 不匹配）；若三軸跳動劇烈且合力毫無規律，是位元組序或 `ADDR_AI` 沒開。`WHO_AM_I`（`0x00`）應為 `0x05`，讀不到這個值就先查 I2C 位址 `0x6B`。
