## 0. 這份文件是什麼

前一版是產品構想草案，以 Waveshare 規格頁為依據，把板子的能力當成「規格表上有就能用」。這一版把它改寫成可執行的企劃：**每一條功能都對照本專案 `docs/notes/` 的實機驗證結果裁決一次**，撐不住的砍掉或延後，並附上排程與驗收條件。

草案的核心主張——「Ritual Loop 才是產品，不要做成掌上算命機」——完全保留。被改掉的是實作路徑，不是產品定位。

**本次撰寫時裝置未連接**（`/dev/cu.*` 只有 Bluetooth 與 debug console，無 `usbmodem`），因此沒有新增實測。以下所有硬體數字都出自 repo 內既有的實機紀錄（2026-08-06 / 08-09），來源逐項標註。標為「未驗證」的項目，代表這份企劃刻意不替它背書。

## 1. 硬體底線

實機讀取的結果（[CLAUDE.md](../../CLAUDE.md)、[docs/notes/](../notes/)）：

| 項目 | 值 | 對設計的意義 |
|------|-----|------|
| 螢幕 | SH8601 QSPI，368×448 RGB565 | 全螢幕一張 = 329,728 bytes |
| **PSRAM** | **無** | 整張 frame buffer 放不進 RAM，只能放 flash |
| SRAM | 512KB（HP SRAM） | LVGL 繪圖緩衝、Wi-Fi、TLS 共搶這一塊 |
| Flash | 16MB；app 4MB + storage 11MB | 目前韌體 746KB，storage 完全空著 |
| 觸控 | `0x38`，**不是真 FT5x06** | 只能裸讀單點座標，沒有手勢引擎 |
| IMU | QMI8658，±8g / 4096 LSB/g | 已可用（[筆記](../notes/qmi8658-accel-minimal-bringup.md)） |
| 音訊 | ES8311 + 功放（TCA9554 bit7） | 播放已驗；**錄音路徑未驗** |
| RTC | PCF85063 @ `0x51` | I2C 掃得到，**尚無驅動、未讀過時間** |
| SD | 腳位已知 | **從未掛載過** |
| 按鍵 | BOOT(GPIO9)、PWR(→AXP2101) | 無 RESET 鍵 |
| 電源 | AXP2101 軟關機至 μA | BOOT **喚不醒 deep sleep** |

### 三條會改變設計的限制

**限制 A：沒有 PSRAM，動畫預算極小。**
368×448 全螢幕 frame buffer 需要 330KB，配不下（[sh8601-lvgl9-area-rounding.md](../notes/sh8601-lvgl9-area-rounding.md)）。現行 LVGL 用 368×64 雙緩衝（92KB），要同時跑 Wi-Fi + TLS 時得降到 368×32（46KB）。
既有的擲筊動畫**實測 21 fps**（2140ms / 46 幀），而那只是兩片半月 sprite 在小範圍內移動。
→ 草案的「全螢幕緩慢煙霧、燭火、神像淡入」在這片板子上做不到。動畫必須限制在小矩形內。

**限制 B：觸控沒有手勢，要自己算。**
這顆晶片只是 I2C 位址與 FT5x06 相同，套官方元件會把它寫到不回應 I2C（[touch-not-real-ft5x06.md](../notes/touch-not-real-ft5x06.md)）。可用的只有：從 `0x02` 連讀 5 bytes 拿到單點 X/Y，20ms 輪詢。
→ 草案的「左右滑動切換空間」要自己從座標序列判定 swipe，並自己接成 LVGL indev。這是一項未開工的工作，不是現成能力。

**限制 C：日常使用的電源模型只有一種。**
BOOT 在 GPIO9，不是 LP IO，喚不醒 deep sleep；PWR 直通 AXP2101（[esp32c6-boot-key-cannot-wake-deep-sleep.md](../notes/esp32c6-boot-key-cannot-wake-deep-sleep.md)）。
→ 「每天打開拜一下」的實際流程是：**按 PWR 開機 → 走完流程 → 軟關機**。所以**開機到正殿的時間是產品體驗的一部分**，目標 2 秒內，Wi-Fi 絕不能在開機路徑上。

## 3. 產品範圍

### 保留的核心

```
入廟 → 參拜 → 稟告 → 求籤 → 擲筊確認 → 解籤 → 留下紀錄 → 離廟
```

### v1 的完整定義

**一台不連網、單機就能走完整套儀式的裝置。** 開機即正殿，全部內容燒在機器裡。

刪掉 Wi-Fi 之後，v1 少了什麼？只有「AI 針對你的問題解籤」這一項。傳統解籤本來就是查表，不需要網路。這個取捨換到的是：開機快、動畫吃得起記憶體、沒有後端要維運、沒有金鑰要藏、沒有語音資料要處理。

### v2／v3

- **v2**：RTC（農曆、初一十五、參拜日期、日夜氛圍）＋ Wi-Fi ＋ AI 解籤
- **v3**：語音稟告（前提是 §7 S7 通過）、OTA、多神明

## 4. 資訊架構與畫面

### 導覽模型

草案的「探索一間廟」保留，但收斂成**一條主軸 + 兩個側翼**，避免自由漫遊導致狀態機爆炸：

```
     ← 參拜簿        正殿（Home）        設定 →
                        │ 上滑／點擊
                        ▼
                   ┌─ 每日參拜（三拜）
                   └─ 問事
                        ├─ 稟告（選類別）
                        ├─ 直接擲筊 ──────────► 結果
                        └─ 求籤 ─► 擲筊確認 ─► 解籤閣
                                      │笑筊：再擲
                                      └陰筊：回求籤
```

側翼只能左右滑進出，深層流程只能循序前進或按 BOOT 返回。

### 畫面規格（368×448）

一次一個焦點，這點沿用草案。

| 畫面 | 主體佔比 | 動畫區 | 互動 |
|------|------|------|------|
| 正殿 | 神像 60% | 香爐上方 ~120×160 香煙 | 點擊進入／左右滑側翼 |
| 每日參拜 | 提示文字置中 | 無（只換字） | IMU 前傾×3 |
| 稟告 | 6 格類別清單 | 無 | 觸控單選 |
| 求籤 | 籤筒 70% | 籤筒 ~180×280 晃動 | IMU 搖動 |
| 擲筊 | 兩片筊 70% | 現行擲筊動畫 | IMU 上下甩／BOOT |
| 解籤閣 | 純文字 | 無 | 觸控上下捲動 |
| 參拜簿 | 條列 | 無 | 觸控捲動 |

**規則：有動畫的畫面不連網，連網的畫面不做動畫。** 理由見 §5.4。

## 5. 技術架構

### 5.1 從單畫面狀態機改成畫面管理器

現行 [main.c](../../src/main.c) 是一支 `while(1)` 直接管擲筊的狀態。加到 7 個畫面後這個結構會撐不住。

改成：每個畫面提供 `enter / exit / tick / on_event`，由一支 `screen_mgr` 持有目前畫面；輸入（觸控、IMU 手勢、BOOT、PWR）統一收在主迴圈，轉成事件送給目前畫面。PWR 軟關機維持全域攔截，任何畫面都能關機。

現有的 `cast_ui.c` 改成實作這組介面的其中一個畫面，內部動畫邏輯不動。

### 5.2 資料層

| 資料 | 存放 | 理由 |
|------|------|------|
| 籤詩＋傳統解籤（60 籤 JSON） | SPIFFS `storage` 分區 | 11MB 空著；`espressif/cjson` 已是相依 |
| 正殿背景／神像圖 | app 分區 const 陣列 | flash 可直接定址，LVGL 從 flash 畫圖不吃 RAM |
| 音效 | app 分區 const 陣列 | 沿用現行 `src/sounds/` 做法 |
| 參拜紀錄 | NVS | 筆數小、要抗斷電 |
| 設定（音量、亮度） | NVS | 同上 |

SPIFFS image 要在**建置時產生後燒進去**，不要讓裝置第一次開機才格式化 11MB 分區。作法待 §7 S3 驗證。

### 5.3 字型：這份企劃最關鍵的技術判斷

現行做法是產生子集字型（[gen-font.sh](../../scripts/gen-font.sh)），因為 LVGL 內建字型只有 ASCII，整套 CJK 塞不下。**畫面出現豆腐方塊就是子集漏字。**

實測基準（`src/fonts/font_zh_28.c`）：147 個中文 + ASCII，`glyph_bitmap` 共 59,853 bytes。換算單一中文字：

| 字級 | 每字約 | 1,500 字 | 4,808 常用字 |
|------|------|------|------|
| 20px 4bpp | ~190 B | ~285 KB | ~0.91 MB |
| 24px 4bpp | ~270 B | ~405 KB | ~1.30 MB |
| 28px 4bpp | ~375 B | ~560 KB | ~1.80 MB |

**傳統解籤沒問題**：語料是固定的 60 篇，全部字元可以事先抽出來。估 1,200~1,500 個相異字，20~28px 都放得進 4MB app 分區。

**AI 解籤有問題**：模型回什麼字無法預知，子集必然缺字，畫面會出現豆腐方塊。這是把 AI 解籤移出 MVP 的**主要技術理由**，不是排程理由。v2 要做的話只有兩條路：

- **(a) 限制輸出字集**：後端把回覆限制在語料字集內，裝置端再做一次缺字檢查，缺字就退回傳統解籤。實作簡單，但會削弱 AI 解籤的語感。
- **(b) 燒一份常用字全集**：4,808 字 @20px ≈ 0.91MB，放 SPIFFS 以 `lv_binfont_create()` 載入。前提是先驗證 LVGL 9.3 從檔案系統載入時的 RAM 佔用（§7 S6）——如果它把整份字型讀進 RAM，這條路在 512KB SRAM 上直接死。

**同時要改腳本**：`gen-font.sh` 目前把字集寫死在腳本裡的字串變數。籤詩語料進來之後這樣維護不了，要改成**從語料 JSON 與 UI 字串檔掃出字集**，語料一改就重產。改字串卻忘了回頭改腳本，結果就是豆腐方塊。

### 5.4 記憶體預算

沒有 PSRAM，512KB SRAM 要同時放 LVGL 緩衝、Wi-Fi、TLS。已知的兩個配置：

| 情境 | LVGL 繪圖緩衝 | 備註 |
|------|------|------|
| 不連網（擲筊現況） | 368×64 雙緩衝 = 92KB | 實測可跑 |
| 連網（天氣看板） | 368×32 雙緩衝 = 46KB | 筆記建議值，再往上會和 TLS handshake 搶堆積 |

`sdkconfig.defaults` 已經為此把 mbedTLS 緩衝縮小並開 `MBEDTLS_DYNAMIC_BUFFER`。

**設計規則**：v1 全程不連網，用 92KB 大緩衝。v2 加 Wi-Fi 時，AI 解籤是純文字畫面、沒有動畫，可在進入該畫面前把繪圖緩衝縮小；**不要在動畫播放中連網**。

實際餘裕要在 M0 用現有的 log 量測後填回本表：

```
I (xxx) app: 就緒，剩餘堆積 xxxxx bytes
```

### 5.5 動畫預算

錨點是實測值：擲筊 46 幀 / 2140ms = **21 fps**，畫面上是兩片小 sprite。

全螢幕重繪一次要送 329,728 bytes 過 QSPI，加上 LVGL 算圖，粗估單幀 30~40ms（QSPI 時脈取元件預設值推算，**未實測**）。所以：

- 全螢幕動畫：**不做**
- 局部動畫：控制在 200×280 以內（~112KB／幀），這是既有擲筊動畫的量級
- 正殿香煙：~120×160（~38KB／幀），10 fps 即可，煙本來就該慢

`gen-sprites.sh` 已經在產筊杯圖，香煙／籤筒沿用同一支腳本擴充，**產物一律不手改**。

## 7. 技術驗證清單

每項都有明確的 pass / fail，不通過就改企劃，不是硬做。

| # | 驗證項 | 通過條件 | 不通過的處置 |
|---|------|------|------|
| **S1** | 觸控接進 LVGL indev + swipe 判定 | 連續 5 分鐘操作無誤判、無 I2C timeout | 導覽改用 BOOT 鍵循環切換 |
| **S2** | PCF85063 讀寫；**AXP2101 軟關機後時間是否還在** | 軟關機 10 分鐘後開機，時間仍正確 | 參拜簿只存「第 N 次」不存日期；農曆／初一十五**整批砍掉** |
| **S3** | SPIFFS 11MB：建置時產 image、掛載時間、讀檔延遲 | 掛載 < 1s、讀一篇籤詩 < 100ms | 改用 read-only FAT，或把語料放 app 分區 const |
| **S4** | 全螢幕背景圖從 flash const 繪製的實測 fps | 靜態畫面切換 < 100ms | 背景改用純色 + 少量向量元素 |
| **S5** | 1,500 字子集字型的實際 flash 佔用 | 加上背景圖後 app 分區仍有 1MB 以上餘裕 | 內文字級降到 24px 或 20px |

## 8. 風險

| 風險 | 影響 | 對策 |
|------|------|------|
| RTC 軟關機後不保時 | 農曆、日期紀錄全部落空 | S2 先驗；企劃已備好降級路徑 |
| 動畫做出來低於 15 fps | 儀式感垮掉 | 動畫區塊上限已寫進 §5.5；先做正殿香煙當作標竿 |
| 籤詩語料擴充後字型爆掉 | 豆腐方塊 | `gen-font.sh` 改成從語料抽字，語料一改就重產 |
| 手持時 IMU 門檻誤判 | 拜到一半誤觸發擲筊 | M4 專門排時間調；每個畫面只認它自己要的手勢 |
